# Матрица доступа, 12 октября 2026

Прогон `dart test` в `server/` против PostgreSQL. Восемь активных пользователей двух компаний и аноним. Пароль сида верный, если не сказано иное.

Свой объект — тот, куда пользователь назначен сидом. Чужой — объект другой компании.

| Запрос | Аноним | Директор | Подрядчик | Технадзор | Наблюдатель |
|---|---|---|---|---|---|
| GET /api/health | 200 | 200 | 200 | 200 | 200 |
| GET /api/auth/csrf | 200 | 200 | 200 | 200 | 200 |
| GET /api/auth/me | 401 | 200 свой профиль | 200 | 200 | 200 |
| GET /api/projects | 401 | 200 только свой | 200 только свой | 200 только свой | 200 только свой |
| GET /api/projects/{свой} | 401 | 200 | 200 | 200 | 200 |
| GET /api/projects/{чужой} | 401 | 404 | 404 | 404 | 404 |
| POST /api/projects | 401 | 201 в свою компанию | 403 forbidden | 403 forbidden | 403 forbidden |
| POST /api/projects без CSRF | — | 403 csrf | — | — | — |
| POST /api/auth/logout без cookie | 401 | — | — | — | — |

Компания А (`a.director`, `a.contractor`, `a.tech`, `a.observer`) видит «ЖК Навои» и не видит «ЖК Чиланзар». Компания Б — наоборот. Это проверено для всех восьми логинов, не только для одной строки таблицы.

Директор А, создавая объект, может прислать `companyId` компании Б. Сервер его игнорирует: новый объект остаётся в компании А. Директор Б этот id получает как 404.

Наблюдатель с верным CSRF на POST получает 403 `forbidden`, не 201.

Отдельно от таблицы ролей:

- неверный пароль — 401, одно и то же сообщение для неизвестного логина;
- пустые поля — 400, до проверки CSRF;
- `a.disabled` — 403 «Учётная запись отключена»;
- пять неудач за 15 минут — шестая попытка 429, даже с верным паролем;
- просроченная сессия — 401;
- выключенный после входа пользователь — 403 на следующем запросе;
- повторный выход без cookie — 401; повтор со старым cookie — 204 и cookie гасится;
- хеши паролей в базе начинаются с `$2`, открытого пароля нет.

Черновик заявки, день 15–16:

- GET /api/requests — 401 анониму, 200 каждому вошедшему;
- GET чужого или несуществующего черновика — 404, в том числе директору того же объекта;
- POST черновика на чужой объект — 404 у всех восьми учёток;
- свой черновик создаёт подрядчик, директор получает 403;
- файл чужого черновика — 404, без сессии — 401;
- в ответе нет `storagePath` и публичной ссылки.

Отправка и согласование, день 17–23:

- отправка без фото — 400, черновик остаётся черновиком и резерв не растёт;
- две отправки в один остаток — одна 200, вторая 409, резерв равен одной сумме;
- тот же ключ и та же версия возвращают прежний результат, другой запрос с тем же ключом — 409;
- отправленную заявку нельзя править;
- чужая заявка для подрядчика другой фирмы и для другой компании — 404;
- наблюдатель видит заявку, решение технадзора ему недоступно — 403;
- подрядчик другой фирмы на решении технадзора — 404;
- директор до технадзора — 409, повторное согласование сумму не меняет;
- отмена до технадзора освобождает резерв один раз, повторная отмена — 409.

Оплата и решение директора, день 24–25:

- оплата без подтверждения — 400, статус остаётся `approved`;
- повторная запись оплаты не увеличивает оплаченную сумму;
- доступный остаток после оплаты не растёт;
- отказ директора освобождает резерв один раз;
- снятие согласования без подтверждения, что банк ещё не платил, — 400;
- новый черновик из отказа не копирует статус и файлы;
- технадзор и наблюдатель оплату не фиксируют;
- чужая компания на этих маршрутах — 404.
