# Запуск в продакшн (MVP)

## Что нужно
- Сервер с Docker, домен, указывающий на него (80/443 открыты).
- Файл `.env.prod` рядом с `docker-compose.prod.yml` (образец: `deploy/.env.prod.example`).

## Переменные
| Переменная | Зачем |
|---|---|
| `APP_ENV=production` | Включает проверки: сервер не стартует с небезопасными настройками (код выхода 78). |
| `COOKIE_SECURE=true` | Cookie только по HTTPS, включает HSTS. |
| `SEED_ON_START=false` | Демо-данные не создаются. |
| `DEMO_ENABLED` | `false` по умолчанию. `true` добавляет на экран входа кнопки демо по ролям: отдельные учебные компании только для чтения, реальные пользователи их не видят, демо не видит реальные данные. Вход в демо без пароля, сессия 2 часа (`DEMO_SESSION_MINUTES`). |
| `DB_PASSWORD` или `DB_PASSWORD_FILE` | Пароль Postgres, не по умолчанию. Файл монтируется в контейнер и не попадает в `docker inspect`. Оба сразу задавать нельзя: сервер не стартует. Файл должен читаться пользователем контейнера (`chmod 644`) и лежать на пути, который видит Docker. |
| `DOMAIN` | Домен для Caddy (сертификат выпускается сам). |
| `BACKUP_DIR` | Каталог бэкапов (виден в админке: «Система»). |
| `MAX_BODY_BYTES` | Лимит тела запроса, по умолчанию 12 МБ. |
| `MAIL_KEY` или `MAIL_KEY_FILE` | Ключ шифрования писем (AES-256-GCM): `openssl rand -base64 32`. Обязателен в production. Храните копию вне сервера: без ключа письма не прочитать. Менять ключ нельзя без перешифровки. Файл и переменную вместе задавать нельзя. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` или `SMTP_PASSWORD_FILE`, `SMTP_FROM`, `SMTP_SSL` | Почта. Без `SMTP_HOST` письма копятся в очереди (админ: «Почта») и не теряются. |
| `DATABASE_URL` | Необязателен. Пустой: API собирает адрес из `DB_PASSWORD` и хоста `db`. Если задан, используется как есть. |

## Первый запуск
```
cd app && flutter build web --release --no-web-resources-cdn && cd ..
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
docker compose -f docker-compose.prod.yml exec api /app/bin/operator bootstrap-admin \
  --login <логин> --name "<Имя>" --password "<не короче 12 символов>"
```
Дальше: войти администратором платформы (при первом входе сервер попросит сменить пароль, если он был временным).

## Как появляются реальные аккаунты
1. Застройщик или банк подаёт заявку на экране входа («Регистрация»). База при этом остаётся пустой, пока заявок нет.
2. Администратор платформы разбирает заявку в разделе «Заявки»: звонки, документы, обязательные проверки.
3. «Одобрить» создаёт компанию, учётную запись директора (логин — почта контакта) и первый объект. Временный пароль показывается один раз и уходит письмом, если задан `SMTP_HOST`. При первом входе пароль нужно сменить.
4. Одобренный банк получает учётную запись администратора банка (логин — почта контакта, временный пароль). Остальных сотрудников банка и застройщика администратор платформы заводит вручную: «Пользователи» → «Создать аккаунт» (пароль показывается один раз). Сброс пароля там же.
5. Если пользователь забыл пароль: «Пользователи» → «Сбросить пароль».

## Демо
`DEMO_ENABLED=true` создаёт учебный мир при запуске (он помечен `is_demo`): застройщик, подрядчик, технадзор, банк и администратор платформы. Любое изменение демо-сессией отклоняется. Реальный администратор в разделах «Компании», «Пользователи», «Заявки», «Журнал», «Почта» демо-данных не видит.

## Бэкапы
`scripts/backup.sh` пишет дамп на хост (каталог `700`, файл `600`). В production-compose каталог бэкапов внутри контейнера базы только для чтения: процесс Postgres не перезаписывает уже снятые копии. Для production передайте `IBUILD_COMPOSE_FILE=docker-compose.prod.yml` в backup/restore-скрипты. Расписание — `scripts/install-backup-schedule.sh`. Восстановление — `IBUILD_COMPOSE_FILE=docker-compose.prod.yml scripts/restore.sh <каталог>`: оно создаёт базу `ibuild_restore` и не меняет рабочую `ibuild`. Проверьте восстановление на копии до запуска.

## Чек-лист перед запуском
- [ ] `/api/ready` отдаёт 200 по HTTPS.
- [ ] Демо-логины отсутствуют (`SEED_ON_START=false`, база чистая). `DEMO_ENABLED=true` допустим: демо изолировано и без паролей.
- [ ] Бэкап создан и восстановлен на тестовой базе.
- [ ] Пароль администратора платформы сохранён в менеджере паролей.

## Почта
Напоминания банка застройщику и отчёты по расписанию (понедельник, с 9:00 по Ташкенту, за прошлую неделю, Excel) пишутся в очередь `mail_outbox`. Если задан `SMTP_HOST`, письмо уходит сразу, статус «Отправлено» или «Ошибка». В панели администратора: «Почта» (состояние, очередь, тестовое письмо, повтор). Письма с вложением при ошибке отправляются заново кнопкой «Отправить сейчас» в отчёте.

## Внутренняя почта
У каждого пользователя есть ящик внутри iBuild (раздел «Почта»): входящие, отправленные, ответ, удаление, счётчик непрочитанных. Писать можно коллегам по организации, администратору iBuild и партнёрам по объектам (банк ↔ застройщики его объектов). Тема и текст хранятся в базе зашифрованными (AES-256-GCM, ключ `MAIL_KEY`), в очереди внешней почты тоже. Не шифруются отправитель, получатели и время: они нужны для списков. Администратор базы без ключа текст не прочитает, администратор платформы чужие письма в интерфейсе не видит. Напоминания банка застройщику приходят и во внутреннюю почту.

## Пароли
Временный пароль (сброс администратором, доступ после одобрения заявки) надо сменить при первом входе. Сменить пароль можно в любой момент: значок ключа в верхней панели. Остальные сессии пользователя при этом закрываются.

## Известные ограничения MVP
- Правила документов: движок читает версии правил для актов (`act`), счетов (`invoice`) и документов на материалы (`certificate`): для них действие «блок» или «предупреждение» берётся из правил. Остальные строки списка документов остаются справочными.
- Часть сообщений валидации правил и текст отчётов — только на русском; тексты писем только на русском.
- CSP без `unsafe-inline` и без сторонних источников. Сборка `--no-web-resources-cdn` отдаёт CanvasKit с того же origin. Остаётся `wasm-unsafe-eval`: CanvasKit компилирует `canvaskit.wasm` через `WebAssembly.instantiate`. `blob:` нужен загрузчику Flutter для worker. Карта объекта — только кадр `https://www.openstreetmap.org`.
- Контейнеры production запускаются с `no-new-privileges`, `cap_drop: ALL` и `read_only`. Базе добавлены только `CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `SETGID`, `SETUID` (entrypoint Postgres). Caddy — только `NET_BIND_SERVICE`. Данные Postgres и `/app/data/files` остаются на именованных томах. Порт API наружу не публикуется: Caddy подставляет адрес TCP-клиента в `X-Forwarded-For`, и только этот заголовок учитывается в лимите заявок.
- Образ собирается командой выше: веб-клиент кладётся в `app/build/web`, затем `docker compose -f docker-compose.prod.yml build`. Оператор внутри образа: `/app/bin/operator` (`--help` не открывает базу). На целевом сервере выпуск сертификата зависит от DNS.
