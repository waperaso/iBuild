# Контракт API

Один origin. Сессия — cookie `ibuild_session` (`HttpOnly`, `SameSite=Lax`). Изменяющие запросы, кроме получения анонимного CSRF, несут заголовок `X-CSRF-Token`.

Деньги — строка `NUMERIC(18,2)`, например `"17500000000.00"`. Поля `plan`, `reserved`, `paid`, `available` никогда не число. Пустой объект отдаёт `"0.00"`.

План — сумма статей, которые видит текущий пользователь. Подрядчик видит только статьи своей фирмы. Резерв — сумма заявок в `submitted`, `tech_approved`, `approved`. Оплачено — сумма заявок в `paid`. Доступно = план − резерв − оплачено. Черновик бюджет не блокирует и в резерв не входит. Любой другой статус заявки блокирует правку статей.

## GET /api/health

200 `{"ok": true}`. Без сессии.

## GET /api/auth/csrf

200 `{"csrfToken": "..."}` и cookie `ibuild_csrf` без `HttpOnly`. Нужен только для входа.

## POST /api/auth/login

Тело: `{"login": "...", "password": "..."}`.

| Условие | Статус | Что видит человек |
|---|---|---|
| Пустой логин или пароль | 400 | Введите логин и пароль |
| Нет или не совпал CSRF | 403 | Запрос отклонён. Обновите страницу и войдите снова. |
| Неверный логин или пароль | 401 | Неверный логин или пароль |
| Верный пароль, учётная запись выключена | 403 | Учётная запись отключена |
| Пять ошибок за 15 минут | 429 | Слишком много попыток. Подождите и попробуйте снова. |
| Успех | 200 | Экран объектов. Cookie сессии. В теле профиль и новый `csrfToken` |

## POST /api/auth/logout

| Условие | Статус | Что видит человек |
|---|---|---|
| Нет cookie | 401 | Сессия уже завершена. Экран входа |
| Живая сессия и верный CSRF | 204 | Выход на экран входа |
| Повтор со старым cookie | 204 | Сессия уже погашена, cookie очищается ещё раз |

## GET /api/auth/me

200 — профиль, членства, `csrfToken`. 401 — нужно войти. 403 — учётная запись отключена уже после входа.

## GET /api/projects

200 `{"projects": [...]}`. Только объекты, где пользователь состоит. Чужая компания в список не попадает.

## GET /api/projects/{id}

200 — карточка, если есть членство. 404 — нет объекта или нет членства. Оба случая выглядят как «Объект не найден», чтобы не подтверждать чужой id.

## POST /api/projects

Тело: `{"name": "...", "address": "..."}`. Поле `companyId` игнорируется: объект создаётся в компании сессии.

| Кто | Статус |
|---|---|
| Нет сессии | 401 |
| Сессия без верного CSRF | 403 `csrf` |
| Подрядчик, технадзор, наблюдатель | 403 `forbidden` |
| Директор | 201 и членство `director` на новом объекте |

Директор здесь — тот, у кого уже есть роль `director` хотя бы на одном объекте. Первые объекты пилота создаёт сид.

Карточка объекта включает те же четыре суммы и `budgetLocked`.

## GET /api/projects/{id}/budget

200, если есть членство. 404 — чужой или несуществующий объект.

```json
{
  "locked": false,
  "plan": "17500000000.00",
  "reserved": "0.00",
  "paid": "0.00",
  "available": "17500000000.00",
  "items": [
    {
      "id": "...",
      "title": "Фундамент",
      "amount": "4800000000.00",
      "contractorFirmId": "...",
      "contractorFirmName": "Навои Строй Монтаж"
    }
  ]
}
```

## POST /api/projects/{id}/budget

Тело: `{"title": "...", "amount": "12500000.00", "contractorFirmId": "..."}`. Только директор своего объекта. Сумма строго больше нуля, не больше двух знаков после запятой. Фирма принадлежит компании застройщика.

| Условие | Статус |
|---|---|
| Не директор | 403 |
| Чужой объект | 404 |
| Уже есть заявка не в черновике | 409 `budget_locked` |
| Нулевая, отрицательная или нечисловая сумма | 400 |
| Успех | 201 |

PATCH и DELETE той же статьи подчиняются тем же правилам.

## GET /api/projects/{id}/members

200 `{"members": [...]}` для участника. 404 для чужого объекта.

## POST /api/projects/{id}/members

Тело: `{"userId": "...", "role": "tech", "contractorFirmId": "..."}`. Фирма обязательна только для роли `contractor`. Пользователь должен быть из той же компании. Повторное назначение — 409. Неактивный пользователь — 403. Чужой пользователь — 404.

## DELETE /api/projects/{id}/members/{memberId}

204. Последнего директора снять нельзя: 409.

## GET /api/contractor-firms и POST /api/contractor-firms

Список и создание фирмы подрядчика. Доступно директору компании. Наблюдатель получает 403. Тело создания: `{"name": "...", "inn": "301000003", "contact": "..."}`. ИНН — 9 цифр. Повтор ИНН внутри компании — 409.

## GET /api/company/users

Сотрудники компании сессии. Только директор компании. Нужен, чтобы назначить участника на объект.

## GET /api/requests

Список заявок, которые сессия имеет право видеть. Подрядчик видит свои заявки. Директор, технадзор и наблюдатель не видят чужие черновики: в списке их нет. 401 без сессии.

## POST /api/requests

Тело: `{"projectId":"...","budgetItemId":"...","amount":"2500000.00","description":"..."}`. Только подрядчик, и только по статье своей фирмы. Статус всегда `draft`. Черновик не входит в резерв и не блокирует смету.

| Условие | Статус |
|---|---|
| Не подрядчик | 403 |
| Чужой объект или чужая статья | 404 |
| Пустая статья или сумма | 400 |
| Успех | 201, тело заявки без пути к файлу |

## GET /api/requests/{id} и PATCH /api/requests/{id}

Автор-подрядчик открывает и правит свой черновик. Чужой черновик — 404, в том числе для директора того же объекта. Правка не меняет резерв.

## POST /api/requests/{id}/files

Тело — байты файла, `Content-Type: application/octet-stream`. Тип определяется по содержимому, не по имени. До 5 фото JPEG, PNG или WebP, каждое до 5 МБ, и один PDF до 10 МБ. Только к своему черновику. Ответ: `id`, `contentType`, `sizeBytes`, `kind`. Поля `storagePath` и публичного адреса нет.

Неподходящий файл — 400. Шестое фото и второй PDF — 400.

## GET /api/requests/{id}/files/{fileId}

Байты файла для того, кто видит заявку. Без сессии — 401. Чужой черновик — 404. `Cache-Control: private, no-store`. Каталог файлов не раздаётся как статика.

## DELETE /api/requests/{id}/files/{fileId}

204. Убрать файл можно из своего черновика. Чужой — 404.

## POST /api/requests/{id}/submit

Заголовок `Idempotency-Key` и тело `{"version": 1}`. Подрядчик отправляет свой черновик, если есть хотя бы одно фото и сумма помещается в остаток статьи. Сервер блокирует статью, заново считает остаток и переводит заявку в `submitted`. Сумма попадает в резерв. Тот же ключ и та же версия возвращают прежний результат и не создают второй резерв. Другой запрос с тем же ключом — 409. Сумма больше остатка — 409, черновик остаётся черновиком.

## POST /api/requests/{id}/cancel

Подрядчик отменяет заявку в `submitted`. Резерв освобождается один раз. Повтор с новым ключом — 409.

## POST /api/requests/{id}/tech

Тело: `{"version": 2, "decision": "approve"|"reject", "reason": "..."}`. Технадзор назначенного объекта. Отказ требует причину и освобождает резерв. Одобрение переводит в `tech_approved`, резерв сохраняется. Повторное решение суммы не меняет.

## POST /api/requests/{id}/approve

Директор согласует заявку после технадзора. До проверки технадзора — 409. Повторное согласование суммы не меняет. Резерв сохраняется до записи оплаты.

## POST /api/requests/{id}/reject

Директор отклоняет заявку в `tech_approved`. Тело: `{"version": 3, "reason": "..."}`. Причина обязательна. Резерв освобождается один раз.

## POST /api/requests/{id}/payment-file

Подтверждение оплаты: одно фото или PDF. Директор прикладывает его к заявке в `approved`. Без этого файла запись оплаты не проходит.

## POST /api/requests/{id}/pay

Тело: `{"version": 4, "paidOn": "2026-10-15", "paymentNumber": "ПП-1842"}`. Заявка становится `paid`. Сумма уходит из резерва в оплаченное и не создаёт новый остаток. Повтор с тем же ключом не учитывает сумму второй раз.

## POST /api/requests/{id}/withdraw

Директор снимает согласование до записи оплаты. Тело: `{"version": 4, "reason": "...", "unpaidConfirmed": true}`. Резерв освобождается один раз.

## POST /api/requests/{id}/copy

Подрядчик создаёт новый черновик из отклонённой заявки. Новая заявка не получает прежнее согласование и не копирует файлы.

CSV и резервная копия в эти маршруты не входят.
